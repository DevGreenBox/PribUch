## 1. Что это за проект

Интернет-магазин **«Тепловодоучет»** — продажа **приборов учёта воды и тепловой энергии**.

- **Название:** Тепловодоучет (прежнее рабочее название — ЭВР, заменено 2026-07-28).
- **Ассортимент:** 50–500 товаров.
- **Ценовые сегменты:** Эконом, Средний, B2B-опт.
- **Стек:** чистые **HTML + CSS + JavaScript** (без фреймворков и сборщиков, если явно не решено иначе).

## 2. Объём текущего этапа (важно!)

**Витрина сращена с платформой Admik** (2026-07-28). Прототип перестал быть статикой с
локальным файлом товаров: у магазина есть админка, база данных и публичный API.

- **Бэкенд — платформа Admik** в подпапке [`Uni_BD/`](Uni_BD/) (репозиторий
  `github.com/TarrySeeker/Uni_BD`): админка + PostgreSQL + Storefront API + СДЭК + оплата + CMS.
- **Витрина — тонкий потребитель** `/api/storefront/v1/*`: своей БД и бизнес-логики у неё нет.
  Каталог, цены, наличие, итоги корзины, доставку и заказы считает сервер
  (anti-tamper: витрина шлёт только выбор покупателя — товар, количество, адрес, способ).
- Корзина (какие товары выбраны) остаётся в браузере, `localStorage`; всё остальное — на сервере.
- Витрина по-прежнему **чистые HTML + CSS + JS**, без фреймворков и сборки.
- **СДЭК — БОЕВОЙ (с 2026-07-29):** ключи договора владельца в `.env`, работают живые
  подсказки городов, справочник ПВЗ и расчёт стоимости/срока. Отгрузка — со **своего ПВЗ
  СДЭК VSL16** (Всеволожск, пр-т Всеволожский, 56): `CDEK_SHIPMENT_POINT=VSL16` уходит в
  создание отправления, `CDEK_FROM_LOCATION_CODE=980` (город Всеволожск) — в калькулятор
  (у него параметра shipment_point нет). Авто-создание отправлений намеренно ВЫКЛЮЧЕНО
  (`CDEK_CREATE_ENABLED=false`), накладные заводит менеджер в админке.
- **В mock-режиме (пока нет боевых ключей):** оплата Т-Банка (демо-страница оплаты).
  Это режим самой платформы, а не заглушка в UI: с ключами в `.env` тот же код
  начинает работать по-настоящему.

**Не делать без отдельного решения:** личный кабинет покупателя, СДЭК PAY (в коробке
платформы — Т-Банк), правки бизнес-логики платформы под этот магазин.

## 3. Аудитория и модель продаж

**B2C и B2B-опт равнозначны.** Сайт должен одинаково удобно обслуживать:

- **Розницу (B2C):** быстрый выбор → корзина → оформление гостем.
- **Опт (B2B):** видимость оптовых условий/сегмента, реквизиты в оформлении заказа, возможность крупного заказа. (Отдельного B2B-портала и кабинета — нет, см. п.5.)

Отражай оба сценария в UX: цена/наличие для розницы + понятный путь для опта (напр. блок «Оптовым покупателям», поле реквизитов в чекауте).

## 4. Функции сайта (scope)

| Функция | Статус | Чем обеспечена |
|---|---|---|
| Каталог с категориями | Реальная | `GET /categories`, `GET /products` |
| Фильтры и поиск | Реальная | данные из API, фильтрация/сортировка на клиенте (474 позиции) |
| Карточка товара (PDP) | Реальная | `GET /products/:slug` (артикул, описание, характеристики, фото, остаток) |
| Корзина | Реальная | выбор в `localStorage`, итоги — `POST /cart/quote` |
| Оформление заказа | **Реальная** | `POST /orders` → заказ виден в админке |
| Расчёт доставки СДЭК | **Боевая** | `quote` (стоимость) + `POST /delivery/cdek/calculate` (срок) + `cities`/`pvz` |
| Оплата картой | Реальная в mock-режиме | `POST /payments/tbank/init` → демо-страница оплаты |
| Статус заказа для покупателя | Реальная | `GET /orders/:number?token=` (страница `order-success.html`) |
| Форма обратной связи | Реальная | `POST /leads` → раздел «Заявки» в админке |
| Контакты и реквизиты | Реальная | `GET /settings` (правятся в админке) |
| Накладная СДЭК | Операция админки | печать в разделе «Доставка», не на витрине |
| Email-уведомления | **Нет** | почтового транспорта в платформе нет — вводить отдельно |
| Оплата СДЭК PAY | **Нет** | в коробке платформы Т-Банк; СДЭК PAY — отдельный модуль |

## 5. Товары и каталог

- **Товары простые — без вариаций/модификаций.** Каждый прибор = отдельная карточка. Нет выбора «диаметр/тип» внутри карточки.
- Характеристики (диаметр Ду, производитель, назначение и т.п.) хранятся как **атрибуты товара** и используются в фильтрах и таблице характеристик, но не как варианты для выбора.
- **Личного кабинета / регистрации нет.** Заказ оформляется **гостем** (контакты + адрес; для опта — реквизиты в форме).

### Источник данных каталога
**Источник истины — база Admik**; каталог правится в админке (`/admin/catalog`).
Первичное наполнение перенесено из [katalog.xls](katalog.xls) (таблица:
КАТЕГОРИЯ / МАРКА (ПРОИЗВОДИТЕЛЬ) / Наименование / цена за 1шт) скриптом
[tools/build-catalog-sql.mjs](tools/build-catalog-sql.mjs) → `tools/catalog-tvu.sql` → psql.
Файл [storefront/js/data/products.json](storefront/js/data/products.json) остаётся только
исходником импорта; **витрина его больше не читает**.

Как разложился прайс по модели платформы:
- 10 разделов → корневые категории; 40 подкатегорий (колонка «МАРКА») → дочерние категории;
- 12 производителей (из скобок) → бренды (`brands`), они же фасет «Производитель»;
- 474 товара → простые товары **без вариантов** (у приборов вариаций нет);
- «цена по запросу» (66 позиций) → `base_price = 0` и остаток 0: витрина показывает
  «Цена по запросу» и кнопку «Запросить цену» вместо «В корзину»;
- остатки условные (10 шт у позиций с ценой) — **фактических остатков в прайсе нет**,
  владелец правит их в админке. Повторный импорт остатки не затирает.

- **Всего товаров:** 474 (из них 408 с ценой, 66 без цены → показывать «Цена по запросу»).
- **Категорий:** 10. **Диапазон цен:** 100 – 248 700 ₽.
- Структура записи товара: `{ id, category, brand, name, price }` (`price: null` = цена по запросу).

## 7. Цвета и типографика (дизайн-токены)

Базовая палитра — нейтральная, один акцент. Определяем как CSS-переменные; при необходимости корректируем.

```css
:root {
  /* Нейтральные */
  --color-bg:        #ffffff;
  --color-surface:   #f5f6f7;
  --color-border:    #e2e4e7;
  --color-text:      #1a1d21;   /* почти чёрный */
  --color-text-muted:#6b7280;   /* серый */

  /* Акцент (основной) — синий: технично, доверие */
  --color-accent:      #1e5eff;
  --color-accent-dark: #1746c2;

  /* Акцент (вторичный) — красный: скидки, «горячее», важные бейджи */
  --color-danger:  #e02424;
  --color-success: #1f9d55;   /* «в наличии» */
}
```

- **Решение (утверждено):** **синий (`--color-accent`) — основной акцентный цвет** (кнопки CTA, ссылки, активные состояния, выделения). Красный (`--color-danger`) — скидки, важные бейджи, счётчик корзины и часть логотипа «ТЕПЛО».
- **Типографика:** системный/гротеск без засечек, как в референсе (напр. `Inter`, `-apple-system`, `Roboto`). Строгая шкала размеров, ограниченный набор начертаний (Regular/Medium/Semibold).

## 8. Логотип

- Логотип **шрифтовой, без знака**: «ТЕПЛОВОДОУЧЕТ», где «ТЕПЛО» — красным (`--color-danger`), «ВОДОУЧЕТ» — синим (`--color-accent`). Одинаково в шапке, подвале и мобильном меню. Прежний знак-капля остался в наборе иконок (`I.logo`) неиспользуемым.
- Размер: 21px в шапке и подвале, 18px на планшетах, 16px на узких экранах (длинное слово должно влезать в строку с иконками).
- Разбивка цветом отражает профиль: тепло — красный, вода/учёт — синий.

## 16. Мобильная версия (адаптив)

Отдельного мобильного шаблона нет — одна вёрстка на все экраны (responsive).
Проверенный диапазон: **320 – 1440 px**, горизонтальной прокрутки нет ни на одной странице.

### Точки перелома

| Ширина | Что меняется |
|---|---|
| ≤ 1000px | Hero, PDP, корзина/чекаут и промо — в одну колонку; сетки по 3 в ряд |
| ≤ 860px | **Мобильная шапка** (логотип слева; телефон, корзина и бургер справа, поиск отдельной строкой), меню категорий превращается в панель, выезжающую **от правого края** — с той же стороны, где стоит бургер, фильтры каталога — лист поверх страницы, сводка перестаёт «прилипать», табы PDP равными колонками, зоны нажатия от 44px, шаг между блоками 40px, зазор в сетках плашек и карточек — 8px (половина десктопного) |
| ≤ 640px | Сетки по 2 в ряд, формы в одну колонку, радио-карточки столбиком, позиция корзины перестроена под узкий экран, подвал в одну колонку |
| ≤ 575px | Кнопки hero встают друг под друга — обе по ширине более широкой из них |
| ≤ 560px | Шапка в одну строку: у корзины остаётся только иконка со счётчиком |
| ≤ 420px | Компактные кнопки и карточки товара, подпись под логотипом скрыта |

### Ключевые решения

- **Токены вместо переопределений.** Мобильная типографика и `--header-h` заданы через
  переопределение переменных в [storefront/css/tokens.css](storefront/css/tokens.css). Иначе правила уровня компонента
  (`.hero h1`, `.pdp h1`) перебивают адаптив по специфичности.
- **Шаг между блоками на мобильных — 40px** (`--section-y: 20px`, по 20px с каждой стороны;
  на десктопе 80px). Здесь же был исправлен баг: боковые поля `.container` задавались
  сокращением `padding: 0 …`, и в медиазапросе оно обнуляло вертикальные отступы у блоков
  `class="section container"` — на мобильных секции стояли вплотную (0px). Теперь только
  `padding-inline`, и `.section { padding-block: var(--section-y) }` работает на всех ширинах.
- **`minmax(0, 1fr)` во всех сетках.** С обычным `1fr` минимальная ширина содержимого
  («Электротехническое оборудование», длинные артикулы) раздвигала сетку за пределы экрана —
  это была причина горизонтальной прокрутки на главной, «Производителях» и «О компании».
  Плюс `overflow-wrap: break-word` в `body` и `hyphens: auto` в плитках категорий.
- **Поля ввода — 16px на мобильных.** Меньший кегль заставляет iOS зумить страницу при фокусе.
- **Выезжающие панели** (меню и фильтры) — в [storefront/js/site.js](storefront/js/site.js): `setNav()` / `setFilters()`
  плюс `body.is-locked` (блокировка прокрутки страницы под панелью), затемнение фона, закрытие
  по Esc, `aria-expanded` / `aria-hidden`. Обе панели закрываются при переходе на десктопную
  раскладку — через слушатель `matchMedia`, ссылка на `MediaQueryList` хранится в `EVR.ui.mqDesktop`
  (без внешней ссылки объект вместе со слушателем может быть собран сборщиком мусора).
- **Лист фильтров** ([storefront/catalog.html](storefront/catalog.html)): шапка с крестиком, прокручиваемая середина
  (`.filters__scroll`) и кнопка «Показать N товаров» внизу. Выбор категории **не** закрывает лист —
  число найденных обновляется на кнопке, на кнопке «Фильтры» видно количество активных условий.
- **Позиция корзины** на узком экране — сетка из именованных областей
  (`media / info / qty / sum / remove`), классы выставляются в [storefront/js/cart.js](storefront/js/cart.js).

### Что осознанно не делали

- Нет отдельного мобильного меню-«таббара» снизу и нет липкой кнопки «Оформить заказ» —
  сводка заказа и так завершает страницу.
- Поиск остаётся видимым в липкой шапке (второй строкой): для каталога на 474 позиции это
  важнее экономии ~46px по вертикали.
